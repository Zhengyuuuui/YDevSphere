# YDevSphere v0.2 · Scanner 迭代方案

> 维护人：总负责人 · 状态：方案定稿（待拆 sprint 执行）
> 前置：v0.1 Plus2 已收尾（`cargo test` 63 passed，`pnpm build` 0 类型错误）
> 定位：v0.2 两大主线之一（① 前端重构 ② Scanner 迭代）

---

## 一、背景：v0.1 Scanner 的缺陷

基于代码确诊的两大核心缺陷：

| # | 缺陷 | 现象 | 根因 |
|---|---|---|---|
| 1 | **无同步/清理** | 删除项目后重新扫描仍在首页 | `upsert_projects` 只增改不删，`scan_projects` 无 reconciliation |
| 2 | **无聚合根归并 / 单一深度假设** | 只扫到 `sub2api/frontend`，不识别 `sub2api/` 根 | `collect()` 遇到清单即 return，不识别多包/聚合根；假定「工作区下一层就是项目」 |

此外，v0.1 假定「工作区 = 项目目录」，无法应对「`~/Documents` 下是 学习/工作/项目 等分类目录，再往下才是 project1/projectN」的**任意深度**用户目录结构。

---

## 二、v0.2 目标

> **智能项目边界识别 + 健康度评分 + 按需懒加载目录树**

核心转变：从「扫描时一次性收集项目」转向「**一次彻底扫描建立索引 + 智能项目边界判定 + 运行时按需加载目录树**」。

### 2.1 识别语义（自顶向下递归）

扫描工作区根 R（如 `~/Documents`），对 R 的每个直接子目录 D：

| 情况 | 判定条件 | 结果 |
|---|---|---|
| **① 真项目** | D 含清单文件（`package.json` / `Cargo.toml` / `go.mod` / `pyproject.toml` / `requirements.txt` 等） | ✅ 卡片（健康度高），内部不再拆，作 tree 子结构 |
| **② 聚合根** | D 无清单，但直接子目录含 **≥2 个**真项目/聚合根 | ✅ 卡片（如 `sub2api`），子项目作 tree 子结构 |
| **③ 分类目录** | D 无清单/子项目，但含子目录 | ✅ 可折叠卡片（如 学习/工作），递归深入识别内部真项目；内部无项目 → 低分卡片 |
| **④ 普通目录** | D 无任何项目特征 | ❌ 不生成卡片，仅在父项目 tree 中可见 |

**关键规则（父项目边界优先）**：一旦 D 判定为「真项目」或「聚合根」，**其后代一律不生成卡片**，只作 D 的 tree 子结构。保证 `project1/src`、`project1/node_modules` 不误判。

**深度保护**：递归有上限（默认 6 层，可配置），配合忽略规则控制性能。

### 2.2 卡片类型 & 健康度

| 类型 | 卡片 | 健康度 |
|---|---|---|
| 真项目 | ✅ 高亮卡片 | 高（60-100） |
| 聚合根 | ✅ 卡片 | 中高 |
| 分类目录 | ✅ 可折叠卡片（展开看子项目） | 低（作容器） |
| 普通目录 | ❌ 不生成卡片 | — |

### 2.3 健康度评分（主要标准：文件数适中 + 结构规范）

基础分 + 加权分：

| 维度 | 加分 |
|---|---|
| 含清单文件 | +20 |
| 有 README | +5 |
| 是 Git 仓库（有 `.git`） | +15 |
| 有 CI 配置（`.github/workflows` 等） | +5 |
| **文件数适中**（避免超大/极空） | 适中（约 10-500 文件）高分，过少/过多降权 |
| **结构规范**（`src/`、`cmd/`、`internal/` 等典型目录） | 有规范结构 +10 |

真项目通常 60-100；分类/普通目录 0-40，用户可凭分数区分。

## 三、后端设计

### 3.1 数据模型（新增字段）

```rust
enum ProjectKind { Real, AggregatedRoot, Category }   // 普通目录不入库

struct Project {
    id, name, path, language, framework,
    workspace: Option<String>,     // 归属工作区
    kind: ProjectKind,             // 新增：项目类型
    health_score: i32,             // 新增：健康度
    parent_id: Option<i64>,        // 新增：父项目 id（聚合根/分类目录树形）
    file_count, created_at, updated_at, last_scan_at,
    // 目录树按需加载，不在项目记录中存全量树
}

struct DirNode {                   // 目录树节点（按需返回）
    name, path, is_dir,
    has_manifest: bool,            // 是否为真项目根
    children_count,                // 子项数量（前端判断能否展开）
}
```

### 3.2 Migration

`projects` 表新增列（幂等）：
- `kind`（TEXT，默认 `"real"`）
- `health_score`（INTEGER，默认 0）
- `parent_id`（INTEGER，可空，指向 `projects.id`）

### 3.3 Scanner 重写（`core/scanner`）

- 替换现有 `collect()`，实现上述 4 类语义判定（真项目 / 聚合根 / 分类目录 / 普通目录）。
- **一次彻底扫描**（深度可配置，默认 6 层）+ 忽略规则（预设 + 用户自定义）。
- **同步清理（reconciliation）**：扫描某工作区后，删除该工作区下磁盘上已不存在的项目（消除幽灵项目）。

### 3.4 Command（向后兼容，新增/扩展）

| Command | 说明 |
|---|---|
| `scan_projects` | 扩展返回含 `kind` / `health_score` / `parent_id` 的项目；内部做同步清理 |
| `get_projects` | 扩展返回新增字段；支持按 kind / parent_id 过滤 |
| `get_dir_children(path)` | **新增**：按需返回指定目录的直接子项（`DirNode[]`），供前端懒加载树 |
| `set_ignore_rules` / `get_ignore_rules` | **新增**：忽略规则预设 + 自定义，持久化到 settings |
| `get_project_detail` | 扩展返回新增字段 |

## 四、前端设计

### 4.1 懒加载目录树组件

- 项目详情页新增「目录结构」区块，展示 `tree -L 1`（默认只展示直接子项）。
- 点击文件夹 → 调 `get_dir_children(path)` **实时加载**下级 → 插入展开（性能友好，不一次性渲染全量）。

### 4.2 Dashboard 卡片

- 项目卡片展示健康度评分（进度条/分数）。
- 卡片类型标识：真项目 / 聚合根 / 分类目录（可折叠）。
- 分类目录卡片默认折叠，展开显示内部项目。

### 4.3 设置页 · 忽略规则

- **预设勾选**：运行时产物 / 敏感目录 / 构建产物 等预设类目。
- **自定义添加**：用户可添加自定义目录名/文件名到忽略列表。
- 持久化到 `~/.ydevsphere/settings.json`。

## 五、交互与同步策略

### 5.1 彻底扫描时机
- **首次导入工作区时**做一次彻底扫描建立索引。
- 用户目录结构相对稳定；**结构变化时提示用户重新彻底扫描**（手动触发）。

### 5.2 同步清理
- 每次 `scan_projects` 扫描某工作区时，删除该工作区下磁盘已不存在的项目（消除幽灵项目，解决「删除后仍显示」）。

## 六、验收标准

1. `cargo build` / `cargo test` 通过（新增：4 类判定单测、健康度评分单测、同步清理单测、`get_dir_children` 单测）。
2. `~/Documents/sub2api`、`~/Desktop/diary` 识别为聚合根项目，详情页展示 frontend/backend/bridge 子结构。
3. `CLIProxyAPI` 这类根含清单的项目：只作为一个项目，内部不拆。
4. 删除项目后重新扫描 → 从列表移除。
5. 分类目录（学习/工作）显示可折叠卡片，内部真项目被识别。
6. 前端懒加载树：点文件夹实时加载，不卡 UI。
7. `core/` 无 `use tauri`；既有 command 签名向后兼容。

---

## 七、边界与约束

- Read Only 默认，仅写 `~/.ydevsphere/`（数据库 + settings.json + project.json）。
- 前端不直接访问文件系统，一律走 `invoke()`。
- 跨平台，无 macOS-only 逻辑。
- 忽略规则由用户配置，默认保守（不忽略用户未授权的目录）。
