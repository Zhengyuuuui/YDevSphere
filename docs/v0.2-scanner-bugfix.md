# YDevSphere v0.2 · Scanner 问题定位与修复（阻塞级）

> 维护人：总负责人 · 状态：严重阻塞，需前后端协同修复
> 优先级：🔴 阻塞级
> 本文档供**前端 agent** 与**后端 agent** 共同阅读，但**职责边界不同**——请各自只做自己部分的修复，不要越界。

---

## 一、问题现象（用户报告）

1. **Documents 工作区显示为空**：在 Projects 页选择工作区「Documents」时，列表为空；选择「Desktop」「全部」时有数据。
2. **用户感知「只扫了 Desktop，没扫 Documents」**。
3. **Console 报错**：`TypeError: menuEl.value.contains is not a function`。

---

## 二、后端排查结论（数据库证据）

执行 `sqlite3 ~/.ydevsphere/database.sqlite` 查得：

```
workspace                     COUNT    路径前缀
(NULL)                        42      /Users/zhengyusheng/Documents/liquid glass demo/...
/Users/zhengyusheng/Desktop   23      /Users/zhengyusheng/Desktop/...
```

**确认**：
- **Documents 的项目确实在数据库里**（42 个，来自 `liquid glass demo`）。
- **但它们的 `workspace` 字段是 `NULL`**，而非 `/Users/zhengyusheng/Documents`。
- Desktop 的 23 个项目 `workspace` 正确写入。

**根因**：这些 Documents 项目是**早期（v0.1）手动选择工作区时扫描入库的**。当时 `projects` 表还没有 `workspace` 列（v0.2 Scanner Phase 1 才加）。v0.2 加字段后，**没有对旧数据做回溯迁移**，导致旧项目的 `workspace=NULL`。

**为什么前端 Documents 筛选是空**：前端/后端筛选规则是 `workspace == ~/Documents` 或 `~/Documents/` 开头。而这 42 个项目 `workspace=NULL`，不匹配 → 前端显示空。

---

## 三、问题根因分类

| # | 问题 | 归属 | 性质 |
|---|---|---|---|
| 1 | 旧数据 `workspace=NULL` 未回溯 | **后端** | 数据一致性缺失 |
| 2 | 一键导入/扫描时，已有项目 upsert 可能未更新 `workspace` | **后端** | upsert 逻辑需核查 |
| 3 | 前端「工作区」是单值模型（`string`），无法同时管理 Documents + Desktop | **前端** | 架构模型不足 |
| 4 | `importAll()` 最后只持久化一个工作区，覆盖了另一个 | **前端** | 逻辑 bug |
| 5 | `menuEl.value.contains is not a function` | **前端** | DOM ref 类型问题 |

---

## 四、修复目标（方案 A：多工作区模型）

> 产品方向：**默认扫描全部工作区，用户可切换选择对应工作区。**

最终行为：
- 工作区是**多值集合**（Documents + Desktop + 手动选择的目录）。
- 一键导入把 Documents 和 Desktop **都加入**工作区集合，都扫描。
- 「扫描」默认扫描**所有已添加的工作区**。
- 前端工作区筛选仍可用（全部 / Documents / Desktop / 手动），且能正确显示各工作区项目。

# 五、职责分工（重要！各做各的）

## 🔵 后端 agent 负责（`src-tauri/`）

### B1. 旧数据回溯迁移
- 新增迁移：给 `projects` 表中 `workspace IS NULL` 的旧项目，按 `path` 前缀**回填 workspace**：
  - `path` 以 `~/Documents/` 开头 → `workspace = ~/Documents`
  - `path` 以 `~/Desktop/` 开头 → `workspace = ~/Desktop`
  - 基于 `dirs::home_dir()` 拼接，不硬编码用户名；无法匹配的保持 NULL。
- 迁移必须**幂等**。

### B2. upsert 修正
- 核查 `upsert_projects` 的 `ON CONFLICT(path) DO UPDATE` 是否**更新 `workspace`**。
- 若未更新，改为：`ON CONFLICT DO UPDATE SET workspace = excluded.workspace`（确保扫描到已有项目时 workspace 正确刷新）。

### B3. 扫描写入 workspace 确认
- 确保 `scan_projects(workspace_path)` 为每个识别到的项目写入 `workspace = workspace_path`（含聚合根/分类目录/子项目）。

### B4. 单测
- 新增：回溯迁移幂等、upsert 更新 workspace、扫描写入 workspace 正确。

> ⚠️ 后端**不碰** `src/` 前端代码，不改前端工作区模型。

---

## 🟢 前端 agent 负责（`src/`）

### F1. 工作区改多值集合
- `settings store`：`workspacePath`（单值）改为**工作区集合**（`string[]` 或 `Set`）。
  - 新增 `workspaces`（列表）、`addWorkspace(path)`、`removeWorkspace(path)`、`setWorkspaces(list)`。
  - 保留向后兼容：兼容从后端读取的单个工作区偏好（迁移为单元素列表）。

### F2. 一键导入 `importAll()` 修复
- 把 Documents 和 Desktop **都加入**工作区集合（不再覆盖）。
- 扫描所有加入的工作区；持久化整个工作区集合。
- 需要新增后端「保存/读取工作区列表」接口（见 F4 说明，或后端 B5 补充）。

### F3. 扫描扫全部工作区
- `handleScan()`：遍历所有工作区，逐个 `scanner.scan`；汇总结果。
- 或改为后端提供「扫描多个工作区」的批量入口（与后端协调）。

### F4. 工作区列表持久化接口（前端发起，后端配合）
- 前端需要「读取/保存工作区集合」的能力。
- 若后端无此接口，前端**先发起**需求，由总负责人协调后端补 `get_workspaces` / `set_workspaces`。

### F5. 修复 `menuEl.value.contains` 错误
- 排查 `menuEl` 的 ref 类型/绑定：可能是 `ref(null)` 但类型推断为组件实例，或 `menuEl.value` 不是 HTMLElement。
- 确保 `.contains()` 调用时 `menuEl.value` 是真实 DOM 元素。

### F6. 前端类型/视图适配
- `ProjectView` 等若需 `workspace` 相关，保持与后端字段一致。

> ⚠️ 前端**不碰** `src-tauri/` 后端代码；若需后端接口配合，报告总负责人协调。

## 六、验收标准

1. 数据库：Documents 旧项目 `workspace` 被回填为 `~/Documents`；Desktop 不变。
2. 前端工作区集合：一键导入后 Documents + Desktop 都在集合中。
3. 前端「扫描」扫描全部工作区。
4. Projects 页工作区筛选：
   - 「Documents」显示 `liquid glass demo` 等 Documents 项目。
   - 「Desktop」显示 Desktop 项目。
   - 「全部」显示两者。
5. `menuEl.value.contains` 错误消除。
6. `pnpm build` 0 类型错误；`cargo test` 通过；无回归。
